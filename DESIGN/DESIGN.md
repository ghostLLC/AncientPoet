# DESIGN.md — AncientPoet（鸿雁）

> 版本: v1.0 | 日期: 2026-05-12 | 对应 Phase 1-2

本文档描述 AncientPoet 的设计语言、用户旅程、屏幕规格和组件目录。它与 `ARCHITECTURE.md`（技术架构）互补——本文档回答"做成什么样"和"为什么这样设计"，架构文档回答"怎么实现"。

---

## 1. 产品概述

### 1.1 一句话描述

一个让你与 AI 扮演的古代诗人以"书信"速度交流的应用。不是即时通讯，是"驿路传书"。

### 1.2 核心价值

| 用户痛点 | AncientPoet 的解法 |
|---------|------------------|
| 现代社交太快、太碎片化 | 消息延迟 2 小时到 7 天，强制慢下来 |
| 打字太随意，缺乏深度 | 书信格式引导用户用更长的文字表达 |
| AI 聊天没有"人味" | 每个诗人有完整的性格、生平、文风设定 |
| 历史人物感觉很遥远 | 故事线模式让用户沉浸到诗人的时代 |

### 1.3 目标用户

- 对古诗词/中国传统文化有兴趣的 18-35 岁用户
- 想要"数字排毒"、减少即时通讯压力的人
- 喜欢深度写作、愿意花时间表达自己的人

### 1.4 设备环境

- **首发**：Android 手机（竖屏），最小 5 英寸屏幕
- **后续**：Desktop（Windows/macOS）、Web
- **网络**：非实时同步，容忍长时间离线

## 2. 设计原则

这些原则是 AncientPoet 所有设计决策的基准。每当遇到 UI 选择困难时，回到这五条。

### 原则 1：慢即是快（Slowness as a Feature）

不是"正在加载"的慢，而是"驿路传书需要时间"的有意慢。

- 所有动画时长比标准 Material Design **慢 1.5 到 2 倍**
- 不显示"正在输入..."的状态，诗人不会"正在打字"
- 消息到达用"信使送达"的隐喻，不是"叮"一声推送
- 不催促用户回复——没有"未读"红点，只有"信已收到"的安静状态

### 原则 2：古物感（Antiquity, Not Cosplay）

让人感觉在和古代灵魂通信，不是在玩古风主题皮肤。

- 参考真实书信的物质感：纸、墨、印章、封蜡、绢帛
- 避免过度装饰——不要祥云花纹、龙纹边框
- 字体用宋体/楷体系列（系统内置，不额外引入 Web 字体）
- 颜色来自中国传统颜料体系：朱砂红、藤黄金、花青蓝、墨黑

### 原则 3：信的隐喻（The Letter Metaphor）

所有交互围绕"写信"和"收信"展开，不是"发消息"。

- 发送按钮不是箭头/纸飞机，是信封图标
- 消息气泡是信纸的形状（直角边 + 柔和圆角）
- 对话列表中的每一项是一封"信札"，不是聊天记录
- 收到回信时有"拆信"的微交互（信封展开动画）

### 原则 4：沉浸而非高效（Immersion over Efficiency）

用户打开这个 App 是为了逃离效率工具的世界。

- 单列布局，信息密度低
- 大量留白——像信纸的空白边缘
- 不展示精确的时间戳，用"两天前""约三日后到达"
- 诗人选择页应该像在翻阅一本古人的肖像画册

### 原则 5：诗人第一（Poet First）

诗人是这个产品的灵魂，不是"AI 助手"的皮肤。

- 每个诗人有独立的视觉标识（头像占位色、所属朝代色）
- 诗人的名字和"字"同等展示（如"李白 · 太白"）
- 诗人消息绝不以 AI 身份说话——永远以该诗人的口吻
- 错误/系统消息不以诗人身份出现（用中性系统提示）

## 3. 用户旅程

### 3.1 首次使用：从零到第一封信

```
下载 App → 手机号登录
  → 进入"诗人"选择页（默认显示 5 位免费诗人）
  → 浏览诗人详情：生平简介、文风描述、代表作
  → 选择一位诗人（如李白）
  → 选择模式：
      - 开放式聊天：直接开始书信往来
      - 故事线模式：选择起始年份（如 742 年，长安，李白 41 岁）
  → 看到当前的地理状态：我在长安，李白在长安
  → 提示"同城书信约 2 小时后到达"
  → 写第一封信："太白兄安好..."
  → 发送 → 信封飞出动画 → 返回对话页 → 显示"回信预计 2 小时后到达"
  → 关闭 App，等待推送通知
```

### 3.2 收到回信

```
收到推送："📜 一封来自长安的信已到达"
  → 打开 App
  → 对话列表中该会话卡片有朱红色封蜡标记
  → 点击进入 → 信封展开动画（600ms）
  → 阅读诗人的文言回信
  → 点击"白话"印章按钮 → 文言交叉淡出 → 白话淡入
  → 开始写下一封信
```

### 3.3 地图移动

```
打开地图 → 看到唐朝疆域图（古风绢帛底图）
  → 我在长安（朱红标记），李白在绵州（金色标记）
  → 虚线连接双方位置
  → 下方显示："距离 320 公里，书信约需 4 天到达"
  → 点击"洛阳"城市标记
  → 弹出卡片："洛阳，东都。前往此地？"
  → 确认 → 显示移动时间："骑马约需 6 天"
  → 状态变为"移动中"，位置标记开始缓慢移动
```

### 3.4 故事线推进

```
在故事线模式下与杜甫通信
  → 当前：755 年，长安，安史之乱爆发
  → 对话顶部横幅显示："755 年 · 43 岁 · 长安 · 安史之乱"
  → 信件延迟因战乱 ×1.5 倍
  → 每次通信后年份自动推进 1 年
  → 用户点击横幅 → 出现年份选择器
  → 可以跳转到任意年份重新体验
```

## 4. 视觉语言

### 4.1 色彩体系

所有颜色取材于中国传统颜料和书法材料。

| 色板名称 | 十六进制 | 来源隐喻 | 用途 |
|---------|---------|---------|------|
| **RicePaper** 宣纸白 | `#F5F0E8` | 古籍内页 | 页面背景、诗人消息气泡 |
| **InkBlack** 墨黑 | `#1A1A2E` | 松烟墨 | 正文、标题、图标 |
| **VermilionRed** 朱砂红 | `#C84C3D` | 印章/朱批 | 主按钮、关键操作、故事线紧张事件 |
| **ImperialGold** 藤黄金 | `#C8A45C` | 封泥/牌匾 | 次要强调、分隔线、成就事件、诗人位置 |
| **JadeGreen** 青瓷绿 | `#6B8E7B` | 青瓷釉色 | 辅助元素、链接 |
| **SkyBlue** 天青 | `#7BA7BC` | 汝窑天青 | 极少使用（留白更好） |
| **WarmGray** 古纸灰 | `#8B8178` | 旧纸氧化 | 次要文字、时间标签、非活跃元素 |

**明暗模式**：Phase 1-2 仅实现浅色（宣纸白）主题。暗色模式留待日后——古代书信没有"夜间模式"的对应隐喻。

**色彩使用规则**：
- 宣纸白是默认背景色，绝不使用纯白 `#FFFFFF`
- 墨黑是默认文字色，绝不使用纯黑 `#000000`
- 朱砂红一次最多用于一个 UI 元素（不出现"满屏红"）
- 藤黄金用于装饰性强调，不用于功能性 UI（金色在浅色背景上对比度不足）

### 4.2 字体

| 用途 | 推荐字体 | 备选 |
|------|---------|------|
| 标题（诗人名、品牌名） | 宋体 / Noto Serif CJK SC | 系统 Serif |
| 正文（书信内容） | 楷体 / 系统 Serif | 系统 Sans Serif |
| UI 标签、按钮 | 系统 Sans Serif | — |
| 文言文原文 | 楷体优先 | 宋体 |

**字体使用规则**：
- 标题字号偏大（品牌名 48sp，诗人名 28sp）
- 书信正文字号较大（16sp）且行距宽松（1.8x），模拟信纸阅读节奏
- 中英文混排时中文优先——品牌名"鸿雁"不翻译

### 4.3 间距与留白

- 基础网格单位：8dp
- 页面左右内边距：16dp（手机）/ 24dp（平板）
- 段落间距：16dp
- 卡片间距：8dp
- 卡片内边距：16dp

**关键规则**：宁可多留白，不可挤满。书信的美感在空白处。

### 4.4 圆角与形状

| 元素 | 圆角 | 理由 |
|------|------|------|
| 书信卡片 | 12dp | 模拟信封的微弧边缘 |
| 消息气泡（诗人） | 12dp + 左下 0dp | 信纸从信封中抽出，左下角是折痕 |
| 消息气泡（用户） | 12dp + 右下 0dp | 已寄出的信，右下角封口 |
| 按钮 | 8dp | 方中带圆，像印章 |
| 对话框 | 16dp | 像展开的折页 |
| 诗人头像 | 8dp（小圆角方形） | 像贴在信札上的肖像画 |
| 输入框 | 8dp | 与按钮一致 |

### 4.5 图标

- 使用 Material Icons 默认图标集（不需要额外引入图标库）
- 优先使用描边风格（Outlined/Filled 按需选择）
- 功能映射：
  - 发送 → `Send`（不是纸飞机）
  - 绘画 → `Brush`
  - 图片 → `Image`
  - 返回 → `ArrowBack`
  - 设置 → `Settings`
  - 地图 → `Place`
  - 诗人 → `Person`

## 7. 动画与动效

### 7.1 时长规范

| 动画 | 时长 | 缓动曲线 | 说明 |
|------|------|---------|------|
| 页面转场 | 300ms | `FastOutSlowInEasing` | 淡入淡出（非滑动） |
| 消息到达 | 600ms | `DecelerateEasing` | 从透明+位移到正常位置 |
| 发送信封 | 400ms | `AccelerateEasing` | 信封缩小 + 向上飞出 |
| 印章切换 | 300ms | `LinearEasing` | 文言/白话交叉淡入淡出 |
| 地图标记脉冲 | 1500ms | 循环 | 朱红圆外圈呼吸式缩放 |
| 进度条 | 1000ms+ | `LinearEasing` | 线性进度，暗示"正在进行中" |

### 7.2 关键动效描述

**信封发送动画（400ms）**：
1. 输入区内容缩小并变为信封图标
2. 信封向上平移并逐渐透明
3. 对话列表自动滚动

**信件到达动画（600ms）**：
1. 消息气泡从透明（0%）开始
2. 同时从下方 20dp 处向上滑动到正常位置
3. 减速缓出

**地图标记脉冲（循环 1500ms）**：
1. 朱红圆外圈从半径 10dp 缩放到 16dp
2. 同时透明度从 30% 降到 0%
3. 循环往复

## 8. 声音与触觉

### 8.1 推送通知声音

- 默认：系统默认通知音
- 计划：古风信件到达音效（如信封放置桌面的轻响、火漆封蜡的微响）
- 渠道名称：`letter_arrival`（"书信到达"）

### 8.2 触觉反馈

- 发送信件：轻震动（`HapticFeedbackType.LongPress`）
- 印章切换：轻震动（`Click`）
- 不建议在消息到达时震动——打扰"慢"的体验

## 9. 内容与语调

### 9.1 品牌声音

- **中文品牌名**：鸿雁（不翻译、不缩写）
- **英文项目名**：AncientPoet（用于代码、文档、GitHub）
- **Tagline**：在快时代慢下来，像"当时"一样交流

### 9.2 UI 文案规范

- 所有面向用户的文字使用中文
- 诗人署名使用历史真实署名方式（如"李白 冬月""杜甫 子美顿首"）
- 系统消息用中性语气（"回信预计 2 小时后到达"），不以诗人身份说系统消息
- 错误提示简洁（"发送失败，请重试"），不展示技术细节
- 时间描述用相对模糊的表达（"2 天前""约 4 天后"），而非"2026-05-14 10:00"

### 9.3 诗人署名格式

| 诗人 | 署名示例 |
|------|---------|
| 李白 | 李白 太白 冬月于长安 |
| 杜甫 | 杜甫 子美 顿首 |
| 苏轼 | 苏轼 子瞻 于黄州 |
| 李清照 | 易安居士 于临安 |
| 王维 | 摩诘 于终南山辋川 |

## 10. 无障碍设计

- 所有交互元素有足够的触摸目标（≥ 48dp）
- 色彩不是传达信息的唯一方式（未读标记同时使用图标+颜色）
- 中文文本使用系统字体以便用户自定义字号
- 书信正文字号 16sp 起，保证可读性
- 按钮文字明确（"发送验证码"，不是"下一步"）
